# 微信模拟器验收

这是一条可重复执行的开发验收命令。它使用微信官方开发者工具运行实际的 `mp-weixin` 构建，独立启动随机端口的 API，并创建临时 SQLite、附件目录和小程序项目副本。运行前先构建：

```sh
npm run build:api
npm run build:mp-weixin
```

`miniprogram-automator` 是可选开发工具，不属于应用运行依赖。可以单独装在已忽略的工具目录，也可以使用自己已有的安装：

```sh
npm install --prefix test-results/wechat-tooling --no-save --package-lock=false miniprogram-automator@0.13.0
```

在微信开发者工具中开启本地服务，HTTP 服务端口可配置为 `9432`，也可填工具当前使用的端口；支持无需登录的游客模拟器。Windows PowerShell 示例：

```powershell
$env:WECHAT_CLI = 'D:\微信web开发者工具\cli.bat'
$env:WECHAT_AUTO_PORT = '9431'
$env:WECHAT_IDE_PORT = '9432'
npm run test:wechat
npm run test:wechat -- --media
```

如果开发者工具已使用另一个 HTTP 服务端口，请将 `WECHAT_IDE_PORT` 设为它当前的端口。自动化端口必须空闲；已有其他项目或验收占用时，命令会拒绝连接，请选择另一个 `WECHAT_AUTO_PORT`。命令只关闭本次随机副本，不退出整个开发者工具。

开发者工具报告项目打开后，命令会给自动化监听最多 30 秒连接时间，再用系统信息和当前页面做最多 30 秒的只读就绪探测。每次探测最多等待 1 秒，早期读取不返回时可继续探测；读取到随机项目标记后才开始页面操作。退出时还会检查本次自动化端口是否已释放；若某个工具版本关窗后仍保留监听，会在结果中明确报出清理问题并保留共享 IDE，下次应换用空闲端口。

| 设置                    | 默认值与用途                                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `WECHAT_CLI`            | 官方 `cli.bat` / `cli`；未设置时检查常见安装位置                                                            |
| `WECHAT_AUTOMATOR_PATH` | SDK 包的路径，默认 `test-results/wechat-tooling/node_modules/miniprogram-automator`；可填外部安装的绝对路径 |
| `WECHAT_AUTO_PORT`      | `9431`，仅本机自动化连接                                                                                    |
| `WECHAT_IDE_PORT`       | `9432`，须与开发者工具的 HTTP 服务端口一致                                                                  |
| `WECHAT_TIMEOUT_MS`     | `240000`，整个工作流程的时间上限，范围 `1000`–`1800000` 毫秒                                                |

默认流程通过实际页面输入创建空间、登录、保存心情，从首页空状态进入愿望清单，新增并编辑愿望后返回首页验证预览及点击跳转，从共享日历打开带目标日期的愿望并返回完整清单，写入 `12.34` 并验证数据库保存为 `1234` 分，随后检查全部 13 个页面及运行时异常。

首页截图等待心情保存后的页面刷新完成；保存愿望后的首页滚动到该行，并通过元素位置、高度与窗口高度确认整行在可见区域后，另存 `home-wishes.png`，用于检查真实预览内容。路由巡检等待加载提示结束后再检查错误，避免只检查到标题或保存一张仍在加载的截图。当前脚本预期为 8 项核心检查、`--media` 为 10 项；是否实际通过以当次 `result.json` 为准。首页愿望补齐后的模拟器复验仍停在 App 就绪探测，不能沿用前轮成功记录，见 [本地交付检查记录](VERIFICATION.md)。

2026 年 11 月 19 日的独立原生最小项目（不含 Vue、Wot 或业务代码）也在同一就绪步骤超时，不能把最新首页或宝宝页面记为已通过微信运行验收。本机工具内部将未初始化时的 App 命令排队，`Tool.getInfo` 则可直接响应；因此连接成功并不能证明系统信息、当前页面等 App 方法已可执行。当前保留原有超时与失败报告，未以扩大等待或改写业务作为未经证实的修复。

`--media` 继续验证图片上传、相册记录关联、缩略图出现、签名图片下载字节一致、ZIP 下载、删除测试记录后恢复 ZIP，以及恢复后的照片字节与会话。它对图片/文件选择器、分享文件交接和恢复确认弹窗提供受控返回值；图片上传、文件下载和 ZIP 恢复请求仍通过真实微信接口与临时 API 执行。没有文件分享能力的旧模拟器会验证页面升级提示，并改用原生下载接口检查 ZIP。

每次运行会生成独立名称，并仅在临时副本的 `app.js` 末尾追加随机身份标记；读取到本次应用标记后才会修改接口地址及登录状态。此方式避开游客模拟器对代码包文件读取的限制。仅临时副本使用游客 AppID 并关闭开发域名校验；原始构建与配置保持不变。

正常结束、失败、超时与 `Ctrl+C` 均执行清理。若 SDK 握手或退出一直无响应，外层守护进程会在清理宽限期后终止本次工作进程树，并按本次随机路径补清理。截图、CLI 日志与 `result.json` 留在 `test-results/wechat-verify-<运行编号>/`；出现 `supervisor-error.txt` 表示需要检查异常退出原因。

模拟器验收不覆盖实体手机、真实微信联系人分享、AppID 身份、HTTPS 合法域名和发布审核。缩略图截图用于视觉复核；下载字节验证不等于模拟器图像解码能力验证。详细命令帮助可运行 `npm run test:wechat -- --help`。
